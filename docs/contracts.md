# Контракты генерации и публикации

API принимает DealContextInput и обязательный заголовок Idempotency-Key.
Контекст объединяет товарные позиции, данные сделки и подтверждённые условия.
Повтор ключа с изменённым контекстом возвращает HTTP 409.
Повтор активного цикла возвращает HTTP 409. Завершённый результат воспроизводится из SQLite.

Суммы в JSON сериализуются строками. Политика скидок задаётся сегментом.
Маржа считается без НДС относительно выручки после скидки.
В режиме three_tiers используются уровни скидки 0%, половина запроса и весь запрос.
На согласование отправляется цикл, если хотя бы один вариант нарушает порог.

Порт CRM предоставляет чтение и применение отдельных операций.
Адаптер live читает сделку, товарные строки и реквизиты привязанной компании
или контакта. Входной DTO остаётся источником позиций сметы, себестоимости,
договорённостей и подтверждённых условий. Данные CRM определяют ответственного
менеджера и позволяют подтвердить валюту RUB. Политики smb, mid_market и enterprise
конфигурируются отдельно, прежний сегмент standard поддерживается.

SQLite хранит состояние цикла, данные результата, мок-журнал и bitrix_steps.
Журнал live содержит ключ, отпечаток портала, имя шага, состояние и ответ.
Перед каждым REST-вызовом фиксируется started. После подтверждения сохраняются
done и идентификатор операции. Для безопасного повтора неподтверждённого
соединения или явного отказа до записи применяется retry.
PDF загружается и прикрепляется одной операцией crm.timeline.comment.add через FILES.
Сверка ищет маркер ключа в комментариях и задачах, а изменение сделки проверяет
по сумме, стадии и признаку ручной суммы. При неопределённом исходе и отсутствии
объекта операция остаётся в reconcile до доказательства результата.
Режим CRM фиксируется в ответе цикла и проверяется при сверке.

Ответ включает tokens_in и tokens_out. При отклонении текста включается mode=fallback.
Причина numeric_guard означает срабатывание постфильтра, invalid_copy — ошибку структуры.
При отсутствии подтверждённых условий выставляется need_human и задача менеджеру.
При need_human документ прикрепляется как внутренний проект, без изменения стадии или суммы.

Файлы сохраняются в каталоге цикла. Пути возвращаются для локального использования.
API доступен по 127.0.0.1:8013. UI работает по 127.0.0.1:8503.
