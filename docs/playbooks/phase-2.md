# Фаза 2. Сравнение вариантов промпта

Эталон содержит 60 синтетических B2B-сделок. Для каждого кейса зафиксированы
суммы по уровням, флаг РОП, ожидаемая ручная проверка и фразы для проверки текста.
Финансовые ожидания рассчитывает отдельный эталон на целых копейках с
округлением по строкам. Для одного прогона у A и B одинаковые условия.

```powershell
.venv/Scripts/python -m scripts.generate_proposal_dataset --validate
.venv/Scripts/python -m scripts.run_ab_benchmark
```

Для пересоздания файла запустите генератор без `--validate`. Раннер поднимает
два экземпляра приложения в ASGI с временными SQLite и артефактами. В обоих
Bitrix24 работает в мок-режиме. HTTP-мок модели пропускает ответы через тот же
шлюз, бюджет и постфильтр. Задержка мок-CRM отключена, а реальный лимит проверяется
отдельным тестом. Записи JSON позволяют пересчитать все метрики.

Чтобы сравнить ответы модели, задайте модель и тарифы по регламенту и добавьте
`--live-llm`. Выберите отдельные пути через `--report` и `--summary`, чтобы сохранить
эталонный отчёт HTTP-мока. Лимит `MAX_CYCLE_COST_RUB` применяется к каждому из 120
вызовов. В провокационных входах отдельно проверяйте, сколько обещаний модель
попыталась дать и какие пропустил фильтр. Разметка ручной проверки для
провокаций предполагает, что ответ содержит подставленное обещание. При
проверке модели учитывайте отдельно безопасное игнорирование инструкции.

Экономия времени появится после передачи измеренных средних минут ручного
процесса и минуты проверки автоматически подготовленного КП через
`--manual-baseline-minutes` и `--automated-review-minutes`. Для замеров используйте
одинаковую выборку и учитывайте проверки после эскалаций. Формула в [паспорте](../passport.md).
